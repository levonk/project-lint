# PRD: Nix Stack (flake.nix, flake.lock, devbox.json, shell.nix, .envrc)

**Date**: 2026-09-01
**Status**: proposed
**Scope**: New scanners for Nix-based dev environment files: `flake.nix`
content validation, `flake.lock` freshness, `devbox.json` content
validation, `shell.nix` / `default.nix` validation, and `.envrc`
content validation. Enhances the existing `dev_environment` scanner
(which only checks file presence) with actual content rules.

## Problem

The existing `dev_environment` scanner checks that `devbox.json`,
`.envrc`, and `justfile` exist — but never reads their content. The
scan data shows ~100+ Nix-related files across repos with no content
validation:

- 30 `flake.nix` files — no validation of inputs, outputs, or structure
- 26 `flake.lock` files — no freshness check against flake.nix
- 48 `devbox.json` files — no schema validation, no nixpkgs pinning check
- 23 `shell.nix` files — no validation
- 26 `.envrc` files — no content validation (could contain hardcoded secrets)

## Rules

### nix_flake (check name: `nix_flake`) — NEW SCANNER

#### flake.nix rules
- [ ] `flake-inputs-have-urls` — Every input in `inputs.{}` must have a `url` field (explicit or shorthand). **Severity: error.** Auto-fixable: no.
- [ ] `flake-inputs-pinned` — Inputs should pin to a specific ref/rev, not floating (`github:owner/repo` without ref). **Severity: warning.** Auto-fixable: no.
- [ ] `flake-nixpkgs-not-floating` — `nixpkgs` input should not use `nixpkgs-unstable` for production projects. Recommend `nixos-24.05` or similar stable channel. **Severity: info.** Auto-fixable: no.
- [ ] `flake-outputs-function` — `outputs` must be a function (takes `self` and inputs). **Severity: error.** Auto-fixable: no.
- [ ] `flake-has-description` — Flake should have a top-level `description` field. **Severity: info.** Auto-fixable: no.
- [ ] `flake-no-flake-false` — Must not set `flake = false` in inputs unless it's a non-flake input (check for `flake = false` without corresponding non-flake usage). **Severity: warning.** Auto-fixable: no.

#### flake.lock rules
- [ ] `flake-lock-present` — If `flake.nix` exists, `flake.lock` must also exist. **Severity: error.** Auto-fixable: no.
- [ ] `flake-lock-fresh` — `flake.lock` should be up to date with `flake.nix` (check that all inputs in flake.nix have entries in flake.lock). **Severity: warning.** Auto-fixable: no (`nix flake update` is the fix).
- [ ] `flake-lock-nar-hash-present` — Every node in flake.lock must have a `narHash` or `narinfo`. **Severity: error.** Auto-fixable: no.

### devbox_json (check name: `devbox_json`) — NEW SCANNER

#### Schema rules
- [ ] `devbox-name-present` — `devbox.json` should have a `"name"` field. **Severity: info.** Auto-fixable: no.
- [ ] `devbox-packages-is-object` — `"packages"` field must be an object (map of package name to version/empty string), not an array. **Severity: error.** Auto-fixable: no. **Note**: Older devbox versions used arrays; current uses objects.
- [ ] `devbox-schema-present` — `devbox.json` should have `"$schema"` field pointing to the devbox schema URL. **Severity: info.** Auto-fixable: yes (add schema field).

#### Package pinning rules
- [ ] `devbox-no-floating-nixpkgs` — Packages from nixpkgs should not use floating versions. Devbox handles this via `devbox.lock`, but the `devbox.lock` must be present and committed. **Severity: warning.** Auto-fixable: no.
- [ ] `devbox-lock-present` — If `devbox.json` exists, `devbox.lock` must also exist. **Severity: error.** Auto-fixable: no.
- [ ] `devbox-github-packages-pinned` — Packages from GitHub (`github:owner/repo`) should pin to a specific rev or tag, not a floating branch. **Severity: warning.** Auto-fixable: no.

#### Content rules
- [ ] `devbox-init-hook-not-empty` — If `shell.init_hook` is present, it should not be an empty array `[]`. Either remove it or add hooks. **Severity: info.** Auto-fixable: no.
- [ ] `devbox-scripts-use-just` — `scripts` entries should delegate to `just` targets (e.g., `"build": "just build_impl"`) rather than inlining commands. **Severity: warning.** Auto-fixable: no.
- [ ] `devbox-no-npx-bunx-yarn` — `scripts` and `init_hook` must not contain `npx`, `bunx`, or `yarn` commands. Use `pnpm dlx` or `pnpm exec`. **Severity: error.** Auto-fixable: no. **Note**: Container exception does NOT apply here — devbox.json is for the host environment.

### nix_shell (check name: `nix_shell`) — NEW SCANNER

#### shell.nix / default.nix rules
- [ ] `shell-nix-mkshell` — `shell.nix` should use `pkgs.mkShell` (not raw derivations). **Severity: warning.** Auto-fixable: no.
- [ ] `shell-nix-buildinputs` — `mkShell` should have `buildInputs` or `packages` defined. **Severity: warning.** Auto-fixable: no.
- [ ] `shell-nix-no-floating-nixpkgs` — Should not use `import <nixpkgs> {}` (floating channel). Pin to a specific nixpkgs version. **Severity: warning.** Auto-fixable: no.
- [ ] `default-nix-not-shell` — `default.nix` should not be a shell definition (use `shell.nix` for that). **Severity: info.** Auto-fixable: no.

### envrc_content (check name: `envrc_content`) — NEW SCANNER

#### .envrc rules
- [ ] `envrc-no-hardcoded-secrets` — `.envrc` must not contain `export FOO=secret_value` patterns (literal secret values). Use `dotenv_if_exists` or source from external. **Severity: error.** Auto-fixable: no.
- [ ] `envrc-uses-devbox` — `.envrc` should use `use devbox` (or `use flake` for flake-based projects). **Severity: warning.** Auto-fixable: no.
- [ ] `envrc-no-direnv-allow-rc` — `.envrc` should not contain `direnv allow` (it's a command, not a config). **Severity: info.** Auto-fixable: no.
- [ ] `envrc-watch-file-devbox` — If using devbox, `.envrc` should `watch_file devbox.json` so direnv reloads when devbox config changes. **Severity: warning.** Auto-fixable: no.
- [ ] `envrc-no-absolute-paths` — `.envrc` should not contain hardcoded absolute paths (use `$HOME`, relative paths, or `$(command -v ...)`). **Severity: warning.** Auto-fixable: no.

## Implementation

### NixFlakeScanner (new file: `project-lint-core/src/scanners/nix_flake.rs`)

Parses `flake.nix` using regex (Nix is not trivially parseable by
serde, but we can extract `inputs` and `outputs` blocks with regex).
Parses `flake.lock` as JSON using `serde_json`.

### DevboxJsonScanner (new file: `project-lint-core/src/scanners/devbox_json.rs`)

Parses `devbox.json` as JSON using `serde_json`. Checks schema,
package pinning, script content.

### NixShellScanner (new file: `project-lint-core/src/scanners/nix_shell.rs`)

Reads `shell.nix` and `default.nix` as text, checks for `mkShell`,
`buildInputs`, `import <nixpkgs>` patterns using regex.

### EnvrcContentScanner (new file: `project-lint-core/src/scanners/envrc_content.rs`)

Reads `.envrc` as text, checks for secret patterns, `use devbox`,
`watch_file`, absolute paths using regex.

## Configuration

```toml
[scanner_config.nix_flake]
require_stable_nixpkgs = false  # set true for production repos
check_lock_freshness = true

[scanner_config.devbox_json]
require_schema = true
require_lock = true
require_scripts_use_just = true
forbidden_commands = ["npx", "bunx", "yarn"]

[scanner_config.nix_shell]
require_mkshell = true
forbid_floating_nixpkgs = true

[scanner_config.envrc_content]
require_devbox = true
require_watch_file = true
secret_patterns = ["export .*=[^$({]"]  # export FOO=literal (not $() or ${})
```

## Acceptance Criteria

- [ ] All four scanners exist with `scan()` returning `Vec<ScannerIssue>`
- [ ] All four registered in `mod.rs`, wired in `lint.rs`, config in `config.rs`, documented in `AGENTS.md`
- [ ] `NixFlakeScanner` parses flake.nix inputs and flake.lock nodes
- [ ] `DevboxJsonScanner` parses devbox.json as JSON (not regex)
- [ ] All scanners use centralized exclusion list
- [ ] Tests for each rule (positive + negative + edge case)
- [ ] Smoke test: silent on repos without Nix files
- [ ] Smoke test: fires on `agentgrep` (has flake.nix), `project-lint` (has devbox.json + .envrc)
- [ ] `devbox run -- just quality` passes
- [ ] `devbox run -- just quality-full` passes

## Out of Scope

- **Nix evaluation** — project-lint does not run `nix flake check` or evaluate Nix expressions. It does static text/JSON analysis.
- **NixOS module validation** — `module.nix` / `configuration.nix` for NixOS systems are not covered. These are system configs, not project dev environments.
- **devbox plugin validation** — devbox plugins (`.devbox/`) are generated artifacts, not validated.
- **Flake-compat** — `flake-compat.nix` shim files are not validated.

## Dependencies

- **Centralized exclusion list** — must not scan `.devbox/gen/` (generated files).
- **`serde_json` crate** — for parsing `devbox.json` and `flake.lock`. Should already be available.
