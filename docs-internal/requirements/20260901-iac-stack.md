# PRD: IaC Stack (Terraform, Pulumi, Ansible, Jinja2 Templates)

**Date**: 2026-09-01
**Status**: proposed
**Scope**: New scanners for Infrastructure-as-Code files: Terraform
(`.tf`), Pulumi (`Pulumi.yaml` / `Pulumi.*.yaml`), Ansible playbooks
and roles, and Jinja2 templates (`.j2`). These file types have zero
instances in the current scan but are explicitly planned for future
use (Pulumi is part of the project roadmap). The scanners should be
built now, gated by check names, and silent when no matching files
exist.

## Problem

No IaC validation exists in project-lint. While current repos don't
have `.tf` or `Pulumi.yaml` files, the user has stated Pulumi is part
of the plan, and some open-source projects require `.proto` files
(separate PRD). Ansible is used in CI (`ansible-lint.yml` workflow
exists at the levonk org level). Jinja2 templates are used in
`levonk-base-boilerplate` for devcontainer generation.

The scan data shows:
- 0 `.tf` files — but planned
- 0 `Pulumi.yaml` files — but planned
- 6 Ansible-related files (workflow, inventory scripts)
- 4 `.j2` template files (devcontainer templates)

## Rules

### terraform_lint (check name: `terraform_lint`) — NEW SCANNER

#### .tf file rules
- [ ] `tf-resource-naming` — Resource names should use snake_case and be descriptive (`aws_instance.web` not `aws_instance.foo`). **Severity: warning.** Auto-fixable: no.
- [ ] `tf-no-hardcoded-secrets` — Terraform files must not contain hardcoded secrets (`password = "literal"`). Use variables or data sources. **Severity: error.** Auto-fixable: no.
- [ ] `tf-variable-description` — `variable` blocks should have a `description` field. **Severity: info.** Auto-fixable: no.
- [ `tf-variable-type` — `variable` blocks should have a `type` field (not rely on implicit typing). **Severity: warning.** Auto-fixable: no.
- [ ] `tf-output-description` — `output` blocks should have a `description` field. **Severity: info.** Auto-fixable: no.
- [ ] `tf-provider-version` — `provider` blocks should pin version (`version = "~> 3.0"`), not use unbounded. **Severity: warning.** Auto-fixable: no.
- [ ] `tf-backend-config` — `terraform` block should define a `backend` (remote state). **Severity: warning.** Auto-fixable: no.
- [ ] `tf-no-default-tags-in-resource` — Use `default_tags` in provider block instead of per-resource `tags`. **Severity: info.** Auto-fixable: no.
- [ ] `tf-lockfile-present` — If `.tf` files exist, `.terraform.lock.hcl` should be committed. **Severity: warning.** Auto-fixable: no.

### pulumi_lint (check name: `pulumi_lint`) — NEW SCANNER

#### Pulumi.yaml rules
- [ ] `pulumi-name-present` — `Pulumi.yaml` should have `name:` field. **Severity: error.** Auto-fixable: no.
- [ ] `pulumi-runtime-set` — `Pulumi.yaml` should have `runtime:` field specifying the language runtime. **Severity: error.** Auto-fixable: no.
- [ ] `pulumi-config-present` — `Pulumi.yaml` should have `config:` section for environment-specific values. **Severity: info.** Auto-fixable: no.
- [ ] `pulumi-no-secrets-in-config` — `Pulumi.yaml` `config:` must not contain secret values in plaintext. Use `pulumi config set --secret`. **Severity: error.** Auto-fixable: no.
- [ ] `pulumi-description-present` — `Pulumi.yaml` should have `description:` field. **Severity: info.** Auto-fixable: no.

### ansible_lint (check name: `ansible_lint`) — NEW SCANNER

#### Playbook rules
- [ ] `ansible-no-become-true-at-play` — `become: true` should not be set at the play level (set at task level for granularity). **Severity: warning.** Auto-fixable: no.
- [ ] `ansible-no-hardcoded-vault-password` — Playbooks must not contain `ansible_vault_password` or `vault_password_file` with literal paths. **Severity: error.** Auto-fixable: no.
- [ ] `ansible-no-cowsay` — Playbooks should not set `nocows: 1` (irrelevant to linting). **Severity: N/A.** Skip.
- [ ] `ansible-task-name-present` — Tasks should have `name:` field for readability. **Severity: warning.** Auto-fixable: no.
- [ ] `ansible-no-command-shell` — Avoid `command` and `shell` modules when a dedicated module exists. **Severity: info.** Auto-fixable: no.
- [ ] `ansible-handler-uses-handler` — Handlers should be notified, not called directly. **Severity: warning.** Auto-fixable: no.

#### ansible.cfg rules
- [ ] `ansible-cfg-no-host-key-checking` — `ansible.cfg` should not set `host_key_checking = False`. **Severity: error.** Auto-fixable: no.
- [ ] `ansible-cfg-vault-password-file` — `ansible.cfg` should not set `vault_password_file` to a committed path. **Severity: error.** Auto-fixable: no.

### jinja_template (check name: `jinja_template`) — NEW SCANNER

#### .j2 / .jinja2 file rules
- [ ] `jinja-no-secret-literals` — Templates must not contain `{{ secret_value }}` or `{{ vault_password }}` literal variable names that suggest hardcoded secrets. **Severity: warning.** Auto-fixable: no.
- [ ] `jinja-no-raw-include` — Templates should use `{% include %}` / `{% extends %}` rather than inlining content. **Severity: info.** Auto-fixable: no.
- [ ] `jinja-sandbox-filters` — Templates should not use `| eval` or `| exec` filters (security risk). **Severity: error.** Auto-fixable: no.
- [ ] `jinja-no-absolute-paths` — Template paths in `include`/`extends` should be relative, not absolute. **Severity: warning.** Auto-fixable: no.

## Implementation

All scanners parse their respective files as text or YAML and check
patterns. Terraform uses HCL syntax — regex/line parsing (not full HCL
parsing). Pulumi and Ansible are YAML — `serde_yaml`. Jinja2 templates
are text — regex for `{{ }}` and `{% %}` patterns.

## Configuration

```toml
[scanner_config.terraform_lint]
require_backend = true
require_lockfile = true
forbid_hardcoded_secrets = true

[scanner_config.pulumi_lint]
require_config = true
forbid_secrets_in_config = true

[scanner_config.ansible_lint]
forbid_host_key_checking = true
require_task_names = true

[scanner_config.jinja_template]
forbidden_filters = ["eval", "exec"]
forbid_absolute_paths = true
```

## Out of Scope

- **Terraform plan/apply** — no `terraform plan` execution.
- **Pulumi preview** — no `pulumi preview` execution.
- **Ansible syntax check** — no `ansible-playbook --syntax-check` execution.
- **CloudFormation** — `*.json` / `*.yaml` CloudFormation templates not covered. Future scanner.
- **CDK** — AWS CDK / CDKTF / Pulumi CDK not covered. These are code, not config.
- **Helm charts** — `Chart.yaml` / `values.yaml` not covered. Future scanner.
- **Kustomize** — `kustomization.yaml` not covered. Future scanner.
- **Crossplane** — Crossplane manifests not covered. Future scanner.

## Dependencies

- **Centralized exclusion list** — must not scan `node_modules/`, `target/`, `.terraform/` (Terraform plugin cache).
- **`serde_yaml` crate** — for Pulumi and Ansible YAML parsing.
