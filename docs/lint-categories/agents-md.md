# AGENTS.md Rules

AGENTS.md rules validate the binding-contract structure of `AGENTS.md`,
`CLAUDE.md`, and `AGENT.md` files — the agent-directives contracts that
govern how AI agents work in a repository.

## Configuration

```toml
[scanner_config.agents_md]
require_usage_protocol = false
require_jit_index = false
check_child_chain = true
attribution_patterns = ["Generated with [Devin]", "Co-Authored-By: Devin", "Generated by AI"]
```

## Rules

- `agents-md-usage-protocol` (info): AGENTS.md should contain a "Usage
  Protocol" section describing the binding-contract nature.
- `agents-md-jit-index` (info): AGENTS.md should contain a "JIT Index" or
  table of contents for quick navigation.
- `agents-md-no-absolute-paths` (warning): AGENTS.md must not contain
  absolute filesystem paths (`/Users/...`, `/home/...`).
- `agents-md-no-ai-attribution` (error): AGENTS.md must not contain AI
  tool attribution ("Generated by", "Co-Authored-By: Devin").
- `agents-md-child-chain` (warning): Referenced child `AGENTS.md` files
  must exist on disk.

## Examples

✅ Good: `## Usage Protocol` heading present, relative paths only, no AI
attribution.

❌ Bad: `/Users/micro/code` absolute path (warning).

❌ Bad: `Co-Authored-By: Devin` attribution (error).

❌ Bad: Reference to `./sub/AGENTS.md` where `sub/AGENTS.md` does not
exist (warning).

## Overlap with markdown_frontmatter

The `markdown_frontmatter` scanner validates generic `.md` YAML
frontmatter (title, synopsis, tags). The `agents_md` scanner targets
only the special agent-contract filenames (`AGENTS.md`, `CLAUDE.md`,
`AGENT.md`) and checks body structure, not frontmatter.
